# 刻页 · 网页录制（测试版 v0.1）

## 功能
- 刻页：记录网页的声音与画面；采用方案 C 的五段声波标识、青柠绿和深色组件体系
- 录制当前 Chrome 页签的视频（含网页声音）或只录制音频
- 视频按开始录制时网页可视区域的比例，限制在最高 1920 × 1080 内，不放大小画面，整段保持固定尺寸。调整浏览器窗口或进入 / 退出全屏不会改变文件尺寸；比例变化时等比保留完整画面，可能出现留边。
- 暂停 / 继续 / 结束录制，不再设置官方示例的 30 秒自动结束
- 录制结束后自动进入本地编辑器
- 深色剪辑工作台：录制列表、中央预览、底部时间轴与片段设置
- 紧凑自适应界面：随窗口宽高分配预览空间，小屏缩小间距，窄窗口自动上下排列；图标按钮可悬停查看用途
- 视频缩略图、实际音频波形、拖动选区、精确时间输入、撤销 / 重做
- 预览选中片段，一键导出并下载；支持预览倍速和音量调整
- 视频导出支持 MP4 / WebM，音频导出支持 MP3 / WAV；默认 MP4 / MP3，原始录制仍为 WebM
- 视频录制和导出最高 1080p，超出时等比缩小；导出保留源视频的实际帧率与时间戳，不强制转换为固定 30fps
- 原始录制分块保存在本地 IndexedDB；视频在独立线程中转换，逐块写入浏览器本地文件存储，不上传内容，也不需要安装助手

## 安装
1. 解压 ZIP 文件。
2. 在 Chrome 地址栏打开 `chrome://extensions/`。
3. 开启右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择解压后的 `extension` 文件夹（里面直接有 manifest.json）。
5. 访问普通网页，点击扩展图标，选择「录制视频与声音」或「仅录制声音」。
6. 点击「结束并编辑」，扩展会自动打开编辑器。
7. 拖动时间轴左右两端的绿色手柄，亮色区域就是要保留的片段；也可以在右侧输入开始 / 结束时间。
8. 点击「预览片段」检查效果，在右侧「文件格式」选择 MP4 / WebM（视频）或 MP3 / WAV（音频），点击右侧面板底部「导出片段」（与删除按钮同一行），处理完成后会自动开始下载。

如果已经安装旧版，在 `chrome://extensions/` 点击本扩展的「重新加载」，再刷新已打开的编辑器即可。无需卸载，保留浏览器内的历史录制。

## 编辑器操作
- 点击或拖动时间轴任意位置，定位播放画面 / 声音；绿色两端手柄调整片段范围。
- 开始 / 结束时间支持 `01:23.50`（分:秒）或直接输入秒数，例如 `83.5`。最短片段为 0.5 秒；更短的原始录制可以完整导出。
- 点击「设为起点 / 终点」或右侧「定位」，使用当前播放位置作为剪辑边界。
- 支持撤销、重做和「重置选区」；所有裁剪只影响导出文件，原始录制不变。
- 音频模式显示音频波形，视频模式显示画面缩略图和音轨波形。波形读取失败或文件超过 96 MB 时显示提示，不影响时间轴裁剪。
- 时间轴先显示首帧，再渐进补齐缩略图；缩略图和波形分析结果保存在本地缓存，再次打开或刷新时直接复用。预览波形采用较低采样率分析，不改变原始文件或导出音质。删除录制时会一起清除对应缓存。
- 「导出片段」完成后自动下载，也可以点击「再次下载片段」。下载统一通过导出入口完成。
- MP4 使用 H.264 视频和 320 kbps AAC 音轨；MP3 使用本地编码器，以 192 kbps 导出，支持单声道和双声道。切换格式后需要重新导出。
- 录制维持原来的最高 30fps，实际帧率受源画面和设备负载影响。MP4 和裁剪后的 WebM 保留源视频的实际帧率与时间戳，不再为固定 30fps 重采样。符合 1080p 尺寸限制的整段 WebM 直接保存原始录制；旧版超出尺寸限制或无法确认固定尺寸的录制需要转换。
- 1080p 的目标视频码率为：录制 WebM 约 25 Mbps、MP4 导出约 20 Mbps，较小尺寸随像素数调整；分别以 25 / 20 Mbps 为上限。码率是目标值，静态画面和不同编码器的实际体积会不同。
- MP4 每秒设置一个关键帧，便于剪辑软件定位。录制本身使用有损编码，旧录制中已经压缩掉的细节无法通过高码率导出恢复。
- MP4 使用固定尺寸的 H.264（avc1）和 AAC，尺寸始终限制在 1920 × 1080 内，等比缩小、不放大，并将奇数尺寸向下对齐至偶数像素。若设备编码器拒绝该尺寸或编码配置，会自动从选区起点重新尝试兼容软件编码，仍遵守相同尺寸限制。旧版变尺寸录制也会按固定画布导出，比例变化时等比保留完整画面，可能出现留边。处理中和完成后会标明兼容模式，原始录制不变。
- 预览倍速和音量只用于预览，不改变导出文件。导出视频时页面会显示进度，并暂时锁定文件切换和剪辑操作。可切换到其他标签页，完成和下载结束前请保持编辑器打开；关闭浏览器、系统休眠仍可能中断处理。
- 导出完成前会检查音视频轨道、所选时长，以及开头、中间、末尾画面能否解码。失败会清理未完成的导出文件并保留原始录制。
- 录制分片与恢复记录一起保存；浏览器意外退出后，下次打开编辑器可恢复已经成功保存的部分。最后未落盘的片段无法保证恢复。
- 左侧选择其他录制；「删除这条录制」会永久删除原始文件，需要确认。

| 快捷键 | 操作 |
| --- | --- |
| 空格 | 播放 / 暂停（焦点在时间轴或页面空白处时） |
| I / O | 将播放位置设为起点 / 终点 |
| ← / → | 播放位置前后微调 0.1 秒；按住 Shift 为 1 秒 |
| Ctrl / ⌘ Z | 撤销 |
| Ctrl / ⌘ Shift Z | 重做 |

时间轴手柄获得焦点后，也可使用方向键微调边界，Home / End 移动到允许的最前 / 最后位置。

## 注意与限制
- 当前是面向测试的最简版本，未经过完整的不同操作系统/Chrome 版本端到端测试。
- 视频裁剪采用 WebCodecs + Mediabunny 从原始文件解码、编码和封装，不依赖隐藏播放器、画面渲染回调或原速播放。速度取决于分辨率、设备和编码器，并非无损剪切。对 Opus 音轨按原始分片时间戳对齐，保留间隔，避免长时间录制后声音逐渐提前。完整 WebM 在已确认固定尺寸符合 1080p 限制时直接保存原始录制；其他 WebM 使用同一文件转换流程。
- MP4 导出需要 Chrome 的 WebCodecs 支持 H.264 编码，安装时不下载任何编码器。AAC 优先使用系统编码器，不支持时使用随扩展打包的本地 AAC 编码器。不支持 H.264 时 MP4 选项显示为不可用，可使用 WebM。
- 新增 `downloads` 权限用于保存导出文件、观察下载结束和处理下载中断；`unlimitedStorage` 用于大量录制数据和临时文件，避免普通站点配额与自动回收限制，仍受实际磁盘空间约束。详见 [Chrome 扩展存储说明](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)。导出前会估算所需空间，实际写入失败也会保留原始录制。视频缓存过期后会清理；原始录制仅在用户删除或清除扩展数据时移除。
- MP3 在后台线程编码，不上传文件，不需要额外安装软件；WAV 体积较大，适合需要 PCM 音频的场景。
- 录制像素受设备缩放比例和浏览器捕获上限影响，当前录制和导出上限均为 1920 × 1080；超出时等比缩小，暂不提供 4K 输出。MP4 不再使用变尺寸 avc3 编码，以提高 QuickTime 等播放器的兼容性。
- 录音、录像、编辑仅针对当前页签（不录桌面或系统音）。
- 录制保留网页原本的显示，不针对特定平台隐藏进度条、修改样式或调整播放器配置；网页自身显示的进度条等元素也会进入录制画面。
- 可能无法录制 chrome:// 内部页面、DRM 保护的视频/音频等。
- 高画质文件更大：1080p MP4 按目标码率估算约 150 MB/分钟（另计音频），一小时约 9 GB。长视频逐块读取和写入，避免将完整视频解码到内存；仍需预留原始录制、转换临时文件和下载副本所需的磁盘空间。本次改回源帧率并限制 1080p 后未运行测试，不同系统及连续一小时实录仍需分别验证，不能保证所有设备都能以相同速度完成。
- 编辑器只保留**一个连续区间**，不包含分割多段、拼接、多轨和效果器。
- 本地浏览器清除网站/扩展存储或删除扩展可能导致历史录制丢失。重要录制请及时下载。
- 请仅录制自己有权保存的内容，并遵守网站使用条款。

## 架构
以 Google 官方 sample.tabcapture-recorder 的技术方案为参考：Chrome Manifest V3、chrome.tabCapture、Service Worker、Offscreen Document、MediaRecorder；添加了中文录制弹窗、IndexedDB 分块存储和裁剪编辑页面。并非对官方源码的完整逐文件修改；由于开发环境无法直接拉取 GitHub 仓库，采用同一官方架构重新实现。

官方说明：https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture
示例仓库：https://github.com/GoogleChrome/chrome-extensions-samples/tree/main/functional-samples/sample.tabcapture-recorder

视频封装、解码调度和转换使用随包发布的 [Mediabunny 1.65.2](https://github.com/Vanilagy/mediabunny)，AAC 兼容编码使用 `@mediabunny/aac-encoder`。原始许可、可读源码和依赖说明位于 `extension/vendor/mediabunny/`；所有 worker 与 AAC WASM 均随扩展打包，运行时不下载远程代码。构建入口为 `scripts/video-export-worker.mjs` 和 `scripts/build-video-export.mjs`。

MP3 编码使用随扩展打包的 [lamejs 1.2.1](https://github.com/zhuker/lamejs)，其来源、许可、可替换的编码文件与对应源码位于 `extension/vendor/lamejs/`。扩展安装后不需要在线下载编码器。

## 开发验证
本次 1080p / 源帧率调整按用户要求未运行测试。以下测试说明和测量数据来自此前版本；固定 30fps、原尺寸及自动降分辨率的断言需要按新设置调整后再运行，不能作为本次改动已验证的依据。

下载包已包含本地编码器，可以直接加载。修改导出源码后，需要重建随包发布的 worker。开发和测试需要 Node.js 20+、Chrome，以及命令行 `ffmpeg` / `ffprobe`：

```sh
npm ci
npm run build:export
npm test
```

测试在独立的浏览器环境中生成测试录制并验证：空状态、数据库升级保留原录制、渐进缩略图、低采样率波形、刷新和切换时复用缓存（不重复解码）、快速切换录制、拖动裁剪、精确输入、撤销 / 重做、选区预览、快捷键、MP4（H.264 / AAC，含整段与裁剪）、WebM、MP3、WAV 实际文件导出、格式不可用时的回退、响应式布局、删除录制并清除缓存。截图与导出结果保存在 `test-results/`，不会访问日常 Chrome 中的录制数据。macOS 默认使用 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`；其他位置可通过 `CHROME_PATH` 指定可执行文件。测试使用本地 HTTP 页面验证编辑器，不覆盖扩展的页签采集权限流程。

测试同时覆盖「刻页」的品牌名称、Logo 和扩展图标，以及录制弹窗中的待录制、录制、暂停、继续、结束、失败重试状态。弹窗测试模拟 Chrome 扩展消息接口，页面和交互使用实际产品代码。UI 规范的对应关系见 `UI/实现说明.md`。

另外可运行 `npm run test:recording` 检查真实的页签采集和 offscreen 录制链路。此检查需要可加载测试扩展的 Chrome for Testing（默认查找本机 Playwright 浏览器缓存，也可设置 `CHROME_TEST_PATH`），并在独立临时配置中只录制本地测试页面，验证窗口缩放和进入 / 退出全屏时，录制与 MP4 导出仍保持起始尺寸。macOS 上还会调用系统媒体框架验证 MP4 可以播放并完整解码。不会访问日常 Chrome 的网页或录制数据。

`npm run test:video-export` 使用实际的 5120 × 2880 测试视频检查 MP4 原尺寸编码失败后的自动重试，以及裁剪时长、H.264 / AAC、音轨、画面完整性和失败后的资源释放。真实录制测试同时覆盖兼容模式下进入 / 退出全屏时文件尺寸不变。

`npm run test:export-continuity` 使用 35 秒动态画面检查正常导出与兼容编码。测试在独立临时 Chrome 配置中运行，关闭测试框架的强制可见覆盖，让导出标签页真正进入后台，并禁止 HTML 播放、captureStream、渲染回调和 MediaRecorder；逐秒检查画面变化、黑屏、视频帧间隔，以及音视频末尾是否一致。macOS 上还验证系统解码能够到达视频末尾。无图形界面时可设置 `KEYE_HEADLESS=1`。

`npm run test:video-quality` 用 1080p/30fps 无损参考源中的运动画面与细纹理，对比旧 3.5 Mbps 和新 20 Mbps 导出，测量 SSIM / PSNR，验证细节改善、原始尺寸、固定 30fps 与 macOS 系统解码；结果位于 `test-results/quality/metrics.json`。

`npm run test:audio-clock` 用带有时间戳间隔的音频脉冲检查原生 AAC、本地 AAC 和 WebM 的声画时钟，验证声音没有逐渐提前。

`npm run test:export-storage` 检查录制恢复、分片缺失、配额不足、写入中途失败、未完成文件清理、下载中断重试，以及下载结束前保留磁盘文件。

`npm run test:long-export` 检查一小时 1080p/24fps 文件的分块读取、30fps / 20 Mbps 高画质 MP4 导出、108000 帧、音视频末尾、固定帧间隔和多处动态画面；macOS 同时抽查系统解码。此测试使用独立普通浏览器配置，避免隐私模式的内存文件系统配额影响长文件测试。首次运行会生成 `test-results/long/hour.webm`（循环动态测试画面），结果保存在同目录 `metrics.json`，不访问日常浏览器数据。

此前版本画质对比（2026-11-08，固定 30fps 设置）：同一段 1080p/30fps 细纹理无损测试源，旧 3.5 Mbps 的 PSNR 约 37.28 dB，新 20 Mbps 约 39.39 dB；SSIM 从约 0.9125 提高至 0.9241。该测试含逐帧变化的细噪点，用于检查压缩细节损失；这不是所有素材的通用分数或无损承诺。

此前版本长视频验证（2026-11-08，固定 30fps 高画质设置）：一小时 1920 × 1080 / 24fps 循环动态测试源，导出固定 30fps MP4，目标 20 Mbps，输出 108000 帧。编码和内部校验约 405.1 秒（6 分 45 秒），实际文件约 5.71 GB（5.32 GiB）；视频 3600 秒、音频 3600.02 秒，全程帧间隔与首、中、尾画面检查通过，macOS 系统解码抽查通过。实际体积随画面复杂度和编码器变化；这是文件转换测试，不能替代连续一小时真实页签录制和其他设备的验证。
